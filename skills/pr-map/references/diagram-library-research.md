# Diagram library options

Investigated 2026-09-21. The viewer now uses **React Flow + Dagre** for automatic layout, with node dragging and a reset-layout control. Dagre is sufficient for these small flows; React Flow provides the canvas and custom cards. The alternatives below were evaluated before that choice.

The previous map format supplied every node position, SVG edge path, and label coordinate manually. The current [map format](map-format.md) describes connections by node ID, and Dagre calculates positions, edge paths, and label placement.

| Option | Automatic placement and movement | Fit for this viewer |
| --- | --- | --- |
| **AntV X6 + ELK** | X6 provides node movement, HTML/SVG rendering, snapping, and edge routers. ELK supplies automatic placement. | Best fit for retaining plain JavaScript and rich cards. X6 documents a UMD distribution usable without an application bundler. Existing card CSS needs checking inside SVG `foreignObject`. [Quickstart](https://x6.antv.antgroup.com/en/tutorial/getting-started), [HTML nodes](https://x6.antv.antgroup.com/en/tutorial/basic/node), [routers](https://x6.antv.antgroup.com/api/registry/router). |
| **React Flow + ELK** | Custom nodes have dragging and selection; ELK or Dagre supplies layout separately. | Strong option if adopting React is acceptable. Port the cards to React components and introduce a local browser bundle. The code panel can remain separate. [Custom nodes](https://reactflow.dev/api-reference/types/node-props), [layout options](https://reactflow.dev/learn/layouting/layouting), [React dependencies](https://github.com/xyflow/xyflow/blob/main/packages/react/package.json). |
| **Cytoscape.js + Dagre** | Built-in graph interactions and layouts; the Dagre extension provides directed layout. | Straightforward standalone JavaScript with UMD support. Rich HTML cards require an extension or extra rendering work, making it less direct for the existing interface. [Core documentation and HTML extensions](https://js.cytoscape.org/), [Dagre extension](https://github.com/cytoscape/cytoscape.js-dagre). |
| **ELK with the current viewer** | Computes positions and routes, but supplies no rendering or dragging. | Smallest renderer change for automatic placement alone. Still leaves custom dragging and edge updates to maintain, so it does not solve the complete interaction request. [ELK documentation](https://github.com/kieler/elkjs). |

ELK and Dagre are layout engines, not interactive editors. Dagre is the simpler choice for a mostly tree-shaped flow. ELK offers more control over ports, hierarchy, and edge routing, which is useful for branching code flows. React Flow's [comparison](https://reactflow.dev/learn/layouting/layouting) documents these differences. ELK provides a browser-ready bundle and optional web workers; its [README](https://github.com/kieler/elkjs) also notes limitations around incremental layout and standalone routing.

For X6, use ELK to arrange nodes initially or when an explicit “Arrange” control is activated. Let the editor handle subsequent dragging and attached edges. X6's [Manhattan router](https://x6.antv.antgroup.com/api/registry/router) can avoid nodes, with a simpler fallback if it cannot find a route. Do not assume an ELK route computed before a drag remains valid afterward, or that automatic layout guarantees readable labels. Test branches, cycles, long labels, and named lanes against representative maps.

All options can keep the generated viewer local: install pinned dependencies during preparation and copy or bundle browser assets into the output directory. Avoid runtime CDN requests, preserving the [existing viewer requirement](map-format.md#snapshot-and-generated-source). X6 and ELK can use local browser bundles; React Flow adds React and a practical bundling step. A migration should preserve node-click code inspection and method-scoped diffs, retain optional authored positions, and make edge paths derived output. Persistence of manually moved positions would be a separate product decision.
